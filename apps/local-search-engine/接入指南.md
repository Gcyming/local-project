## 三、两种「检索」到底是什么（v3.2.0 关键变化）

v3.2.0 把原来的「联网」和「全网」**合并为一个「全网」模式**，避免和 slime 主程序内置能力割裂：

| 模式 | 数据来源 | 说明 |
|---|---|---|
| **本地** | 页面自建倒排索引 | 选文件夹/文件/拖放建立索引，BM25 排序、命中高亮、分页、全文弹窗 |
| **全网** | ① slime 内置浏览器内核（主）② 自建索引服务（辅，可选） | 优先用内核实时联网检索（Google 式结果）；若 `8600` 服务在线，会把服务命中作为「自建索引 · 补充命中」叠加显示；内核未接入时自动降级为纯服务检索 |

所以「全网」模式下：
- **接入 slime 时** → 走内核真实联网，非空壳；
- **独立打开时** → 内核不可用；若本机起了 `server.py`（8600），则用自建索引结果；两者都没有则给出可操作的提示。

## 四、操作流程

### A. 先让自建引擎跑起来（可选，作为「全网」的补充源）

```bash
# 1) 进入引擎目录
cd core/websearch

# 2) 爬取（从 seeds.txt 出发；建议先用小页数试跑）
python3 crawler.py --db search.db --seeds-file seeds.txt \
    --max-pages 200 --max-depth 3 --delay 1.0

# 3) 建索引（可加 --query 当场试搜）
python3 indexer.py --db search.db
python3 indexer.py --db search.db --query 咖啡

# 4) 起服务（默认 127.0.0.1:8600）
python3 server.py --db search.db --port 8600
```

自检：浏览器访问 `http://127.0.0.1:8600/health` 应返回 `{"ok":true}`。

### B. 打开前端页面

- **独立使用**：双击 `apps/local-search-engine/index.html`（或用浏览器打开）。
- **接入 slime 后使用**：由主程序加载该页并注入内核桥（见下节）。

### C. 使用

1. 顶部切换 **本地 / 全网**。
2. **本地**：点「选择文件夹 / 文件」或拖入，建立索引后即可检索。
3. **全网**：直接输入关键词回车；命中来自内核，服务在线时会追加补充命中。
4. 顶栏徽标会显示当前引擎状态（已接入内核 / 索引 N 页 / 未接入…）。

## 五、接入方法（让「全网」走 slime 内置浏览器内核）

页面通过**两条通道**连接宿主，二者具备其一即视为「已接入」：

- **通道①（主用）**：宿主注入对象 `window.SlimeBrowserHost`。页面侧判据 = `window.SlimeBrowserHost` 是否存在 + `stats().onlineHost`。
- **通道②（降级）**：`postMessage` 桥，仅当页面被**同源 iframe** 承载时可用（webview 里天然失效）。

### 宿主对象契约（`window.SlimeBrowserHost`）

| 成员 | 作用 |
|---|---|
| `name` | 字符串；显示为页面顶栏「已接入：X」角标 |
| `query(q)` → `Promise<{ok,engine,engineName,items}>` | 联网检索（宿主侧唯一产地） |
| `notify(evt)` | 上报页面事件（`ready`/`mode`/`results`/`open`/`page`/`index`/`error`） |
| `onTheme(cb)` / `getTheme()` | 主题订阅 / 主动拉取 |
| `reportTheme(detail)` | 页面回传主题（本版页面已不再主动切换，仅透传） |

### 宿主侧接线位置（在 slime 仓库内）

1. **内核检索实现**：`core-ts/src/search/onlineSearch.ts` —— 全网检索的唯一产地。
2. **桥接与注入**：
   - `gui/src/main/searchBridge.ts` —— IPC 注册 + 来源白名单；
   - `gui/src/preload/searchHost.cjs` —— guest preload，注入上面的 `window.SlimeBrowserHost`。
3. 把搜索页加载进主窗口（**同源 iframe** 或宿主支持的嵌入方式），并确保 preload 生效。

> 页面侧无需改动，接入与否由「桥在不在」自动判定。

## 六、注意事项 & 常见坑

1. **端口/地址**：服务默认 `127.0.0.1:8600`。页面内「全网」面板可改服务地址并持久化；换了端口记得在页面里点「重新连接」。
2. **CORS**：`server.py` 已全开，跨源 `fetch` 可用；若你反代/改网关，需自行保留 CORS 头。
3. **爬虫礼貌性**：`--delay` 为同主机请求间隔（默认 1.0s），别调太小；尊重 `robots.txt`（除非明确 `--ignore-robots`，不推荐）。建议先 `--max-pages` 小值试跑。
4. **`page` 是 0 基**：接口 `/search?q=…&page=0&size=10`，第 1 页是 `page=0`。
5. **主题**：v3.2.0 **已取消页面自己的配色切换**（不再有切换按钮、不写 localStorage）。页面只**被动跟随** slime 主程序下发；独立打开时跟随系统明暗。主程序若要设置，仍可调用 `window.SlimeSearch.setTheme('dark'|'light'|'auto')`，或经 `onTheme` 推送。
6. **联网/全网 webview 通道**：`postMessage` 在 webview 里失效，主题与事件请走注入对象通道（`window.SlimeBrowserHost`）。若你沿用右栏 `<webview>` 方案，确保 guest preload 已注入该对象。
7. **替换文件**：本次前端已升级到 **v3.2.0**，请用新的 `index.html` **整体替换**旧文件（不要和 v3.1.0 混用）。
8. **依赖**：引擎为纯 Python3 标准库 + SQLite，**零第三方依赖**；服务用 `ThreadingHTTPServer`。
9. **数据文件**：`search.db` 是索引库，首次跑 `crawler.py` 后才会生成；换库路径请三处命令保持一致。

## 七、快速排障

| 现象 | 排查 |
|---|---|
| 全网模式提示「未接入内核 · 索引服务未连接」 | ①未在 slime 内运行（无内核桥）；②`server.py` 未启动或地址/端口不对 |
| 顶栏角标无「已接入」 | preload 未注入 `window.SlimeBrowserHost`，或页面不是被宿主加载 |
| `/search` 返回空 | 可能尚未爬取/建索引；先跑 `crawler.py` → `indexer.py` |
| 页面还是旧界面（三个模式） | 仍是 v3.1.0，请用 v3.2.0 的 `index.html` 替换 |
