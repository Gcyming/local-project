本轮修的五件事

  • 箭头方向：ChevronIcon 基准朝右 ▸，全仓约定 open ? 90 : 0。原来写成 collapsed ? 90 : 0，于是展开时朝右、收起时朝下，正好反了。现展开朝下 ▾、收起朝右 ▸。
  • 数量徽标居中：原来靠行盒自然撑高（fontSize:10 + padding:1px 6px），数字在胶囊里上下不居中。现改为固定 height:16 + inline-flex 居中 + tabular-nums + minWidth:28，数字永远居中、位数变化也不跳宽。
  • 整块收紧：标题 6→4px、进度条 6→4px、分组标题上内边距 7→4px、行内边距 5→3px、行间距 2→1px。原来这几层留白叠出约 20px 死区。
  • 分组标题按需出现：只在出现两种以上状态时才打「进行中 / 待办 / 已完成」——一堆同状态任务时标题纯占高。
  • 会话未就绪门闸：sessionId 还没就绪时不渲染任何数据，只给「正在加载会话…」，输入框置灰。

「加载途中冒出旧待办」的真因

TasksTab 拿到的是 props.sessionId ?? ""。会话未就绪时是空串，于是主进程去读 todos_ + "" + .json = data/todos_.json —— 那正好是修复前遗留的孤儿文件的文件名，所以冷启动途中会把上一次的旧计划显示出来。

三层防御：①渲染层 sessionReady 门闸（loadPersisted/flushPersist/拉取三处都有守卫）；②订阅过滤两侧严格匹配（原来 props.sessionId 为空时整条守卫被跳过）；③主进程对空 sessionId 直接拒绝。

另外「刚完成」动画的 diff 基线也带上会话标识了 —— todo id 常是模型自己编的 "1"/"2"/"3"，切会话时新旧 id 撞车会把新会话里本来就完成的项误判成「刚刚完成」而整片闪。

完成瞬间三个动作（未改，保留）

① 对勾「画入」

pathLength=100 归一化路径长度，CSS 里 stroke-dasharray/offset 恒为 100 —— 任何图标尺寸都刚好一划到底。0.3s。

② 删除线「划过去」

text-decoration 不可动画，改用随宽度 0→100% 生长的细线（::after + currentColor）。0.26s。

③ 整行先亮再沉降

背景先落 --success-soft 保持 40%，再用 0.9s 落回透明、透明度过到 0.55。
