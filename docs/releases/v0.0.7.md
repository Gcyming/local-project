## 本版重点

**权限开关真的管用了、更新不再偷偷下载 500 MB、输入区被重做了一遍。**

这一版四组改动全部来自「用户在自己机器上直接看得见」的现场反馈：① 设置里的权限开关此前
形同虚设 —— 关掉「写 / 终端」仍逐次弹窗，而把审批档位调到「无需」又把安全硬规则一起免掉；
② 翻到设置的状态页就静默开始下载 500 MB 安装包，且全程没有一个进度数字；
③ Agent 半天不吐正文时界面毫无反馈、待发指令卡被渲染成「徽标 + 一行黑话」、三个按钮图标
渲染成实心方块；④ 启动加载页放行得太早 —— 门开了、会话历史还没到，中栏是一块看着就绪
实则没接上数据的假空态。

## 一、权限：开关即授权（A-1057）

用户原话：「设置里面控制权限的那一个栏目，给我着重放权给里面的开关，**要给就直接给**，
别每次都要找我要这要那，**沙箱之类的安全工作做好就行**。」

拆成两条互不冲突的目标：**开关打开 = 该类别直接放行**；**安全边界不降级**（靠硬规则 +
沙箱兜底）。实测发现两条都没做到，而且是同一个病：**判据住错了层**。

### 拆出来的五条结构性缺陷（都不是「开关忘了接」）

| # | 缺陷 | 用户可见后果 |
| --- | --- | --- |
| ① | 工具闸门只有**否决权**，「要不要问」由审批回调按「工具是否声明可自动批准」决定，**完全不看开关** | 打开写 / 终端后，`adb_shell`、`adb_push`、`http_create_app` 仍逐个弹窗 |
| ② | 硬规则（`rm -rf /`、受保护源码目录、敏感文件）**只住在审批回调**里，而回调仅在沙箱决定要问用户时才跑 | 免审批档位直接放行 → **安全边界被「免审批」一起免掉**，Agent 能写自己的护栏目录 |
| ③ | 终端类目标取值漏了 `command` 字段 | 目标退化成整串 JSON → 每条 ADB 命令都判「未知命令 → 需确认」，这是「每次都问」最机械的成因 |
| ④ | 沙箱配置对没有 override 的 Agent 硬编码回落 | 设置里的「全局默认审批模式」形同虚设，改动不生效 |
| ⑤ | `slime:term:exec`（IPC 通道）绕过沙箱 | 本轮未动，记录为遗留项 |

### 判据分层：三个纯模块，装配层只接线

| 模块 | 唯一职责 |
| --- | --- |
| `tools/grant.ts`（新） | 类别归属（前缀优先 → 取风险最高类 read < write < terminal < network）+ 开关 → 是否放行 |
| `tools/hard_rules.ts`（新） | 硬规则检查（终端黑名单 / 写路径与受保护目录 / 内网地址）+ 统一的目标取值 |
| `tools/policy.ts`（新） | 闸门顺序固定：**类别否决 → 硬规则 → 放行**；分级：**硬规则 → 开关放行 → 分级 → 未声明则收敛为需确认** |

装配层（`index.ts` / `registry.ts` / `tool_loop.ts`）只剩「查配置 + 组装开关」。闸门从「某条
内联实现」改为**每次工具调用都过判据**，不再存在绕过路径；界面文案也改为「**开关即授权**：
开启 = 直接执行不再逐次弹窗；硬规则不随开关降级」。

顺带修掉设置里两条**误导性描述**（「读」里写着「截屏预览」、「写」里写着「图形控制」）——
描述与实际授权面不符会让用户按错开关。

**守卫**：`a1057-permissions.spec.ts` 41 条（7 组）；新增变异脚本 **34/34 全红**。
重构让一条存量守卫（`network-gate`）锁定的字串随代码消失 —— 按「迁移」处理：断言搬到新家
保留意图，并**补一条接线守卫**（装配层确实委托判据 + 调用时实时读开关）。

## 二、自动更新：由用户主动触发，进度如实报（A-1055）

用户原话：「怎么一有新版本…翻过去就直接显示后台更新了？**要用户主动选择啊**。」

### 四项改动与根因（都是「改回去不报错、只有用户在自己机器上看得见」）

| 项 | 根因（不是表象） | 修法 |
| --- | --- | --- |
| 更新改**用户主动** | `electron-updater` 的 `autoDownload` **默认为 true**，而此前只在「已启用」分支里赋值 → 发行版走「未启用」分支时**从来没人把它设成 false**；手动检查又不受该开关限制，于是面板挂载即检查 | 在任何检查之前先关掉自动下载（配置与初始化两条入口最前调用），退出时自动安装同样关掉；下载必须由界面按钮触发 |
| **下载进度** | 主进程**压根没监听**下载进度事件 → 界面拿不到数字，只能显示一句静态「正在后台下载…」 | 新增进度事件监听（百分比 / 已传 / 总量 / 速率，百分比夹 0–100）+ 下载 IPC 通道 + 界面进度条 |
| 通知**图标** | 旧口径用的**数据根**（打包版是用户目录）里没有图标文件 → 静默退回 Electron 默认图标；且系统通知**头部**图标只认某个注册字段，此前刻意不写 | 改用**安装根**取图标，文件不存在就交给 Electron 兜底而不是塞一个坏路径；URI 由严格校验产生（反斜杠、空格、非位图一律不合格）；幂等判据覆盖全部字段（此前只比一个 → 补字段那版被短路，日志还报「已注册，跳过」） |
| 托盘**常驻** | 旧实现只在「后台模式 + 用户关窗」时才建 → 现象是反的：不要的时候一直显示、要的时候根本没有 | 建窗后立即确保托盘存在；提示文案跟随显示 / 隐藏 / 最小化 / 还原；点击 = 显隐切换；建失败出声 |

同时：状态页挂载时**不再自动检查**（那条路正是「翻到状态页就自动更新」的触发器），
但**保留**用户主动点的「手动检查」—— 从一个极端改到另一个极端同样是缺陷。

**守卫**：`a1055-guards.spec.ts` 17 条（含主进程与渲染层状态联合**逐字相同**）；
新增变异脚本 **30/30 全红**；`a1021-guards` 里一条**与事实相反**的注释一并修正。

## 三、输入区重做：状态行 / 待发指令卡 / 图标（A-1054⑤⑥ · A-1056 · A-1058②③）

### 1. 实时状态行搬到「Agent 输出最下方」

底部的监测栏从此**只报数**（运行指示 + tokens / 耗时 / 速率 / 上下文 / 模型 + 子代理按钮），
状态与激励语整块搬到 Agent 输出之后。状态行**主句是事实、副句是可核对的数字**，
久等才补一句陪伴语 —— 不与事实抢注意力。

渲染成本是这轮的硬约束（用户点名「别再卡顿」）：

- **删掉面板级 4 秒定时器** —— 它每 4 秒把整个 5000 行的聊天面板重渲染一次，正是卡顿的典型形态
- 秒级计时器住在状态行**自己**里（只让这一行重渲染）+ 稳定 props 的记忆化
- 激励语从「阶段已耗时」推导（同种子同结果，不闪动）；阈值与文案池抽为纯模块 `cheerPhrases.ts`

### 2. 待发指令卡改成「用户气泡卡片 + 三个图标」

旧版渲染成「徽标 + 一行纯文本」，用户读到的全是实现词（原话：「即将插入是什么鬼？」）。
现在每条待发指令是一张气泡卡，右侧三个图标：**修改 / 直接插入 / 撤销删除**，
可单独切换插入方式。队列语义抽为纯模块 `instructionQueue.ts`（先进先出、跨会话隔离、
身份用自增 id）；只服务旧开关的 `insertModeToggle.ts` **整模块删除**（调用方已全部消失），
队列里 5 个只被自己测试养着的死导出一并清掉。

### 3. 三个按钮图标渲染成实心方块（A-1058③）

**这不是图标资源缺失，是声明被静默丢弃。** 构建工具把 SVG 引用编译成 URL 编码的 data URI，
并把内部的双引号换成了**单引号**；而 CSS 规范里未加引号的 `url(...)` **禁止**出现单引号 ——
于是整条遮罩声明被解析器丢掉（计算值为「无」），元素只剩一层底色 = 实心方块。

修法是加一层双引号（data URI 内只有单引号、没有双引号，包裹是安全的）。用 Electron 探针
做了双向闭环：未加引号 → 计算值为「无」（等同不设遮罩）；加引号 → 回显出该 URL。

### 4. 待发指令卡位置（A-1058②）

用户原话：「这个插入怎么在输入框内？我要的是在输入框上面的**监测框上面**。」
待发卡从输入框的圆角容器**内部**移到容器**之前**（即整块输入区之上），不再与输入框、
监测栏挤在同一个框里。

### 5. 模型下拉分组头（A-1056）

去掉 CSS 的强制大写 —— 中文与全小写键被大写化后，同一个词以两种「字体」同屏出现的观感问题。

## 四、启动门补上「会话内容」（A-1058①）

用户原话：「这个中间的界面加载要一段时间，**我说话你是听不见吗？给我算在加载界面里面**。」

**根因**：启动门只等 agents / sessions / providers / localModels 四项，**不含中栏自己的内容**。
门放行之后聊天面板才挂载、才去读会话历史 —— 历史到达之前，中栏渲染的是「消息数为 0」的
**空态**：看着已经就绪，实则还没接上数据。用户在这段窗口里说话，自然没有反应。

**修法**：把会话历史并进启动门的等待清单。聊天面板在历史加载**落定**时回执
（**成功与失败都回执** —— 失败不能把用户永久关在加载页）；「欢迎页 / 拿不到 Agent」
这两条不挂载聊天面板的路径由上层自己收尾，**且必须先等会话清单回来**（否则判断恒真 =
提前放行，正是要修的那个洞）。回执函数使用稳定引用，避免被写进副作用依赖后**自激重拉历史**。
加载页的阶段清单同步多出一项。
