## 本版重点

**上下文压缩链真正接上了、聊天面板与设置面板各重做一轮、右侧栏变成能干活的工作面板。**

这一版是自 A-1059 起连续四天的工作总汇（A-1059 ~ A-1125，共 67 项改动），主线有四条：

① **上下文**：此前「压缩」其实只是截断 —— 发送前没有预算门、引擎侧没有保险门、
摘要覆盖不生效、上下文上限不跟随所选模型。现在压缩链是一条**有闸门的链**，
每一环都有判据、每一个「看起来在工作其实一次都没生效」的地方都被点名修掉。

② **Agent 输出的编排**：引导（steer）三态、计划接续、阶段命名、工具卡实时态、
待办全景、思考与正文的吐字渐入。其中「正文后置闸门」曾被**切会话悄悄换回旧实现**，
本版把两条渲染路径合并成**唯一产地**。

③ **设置面板**：左栏 13 个栏目按「重要度 + 使用频率」重新组织成 **4 个语义组**；
各页留白从「每页各写一份」收归共用祖先，13 个页面的左缘第一次对齐。

④ **右侧栏**：新增网页预览、终端 / 文件树的程序化开关、产物文件改动回滚、
屏幕控制的「命中校验」，以及 HTTP 工具产出**任意多文件**本地 web 程序的能力。

## 一、上下文：压缩闸门链与「窗口随模型」（A-1082 ~ A-1090）

本版最重的一块。用户最初的判断是「当前的压缩并非真正压缩、只是 trimming」，
顺着这条线查下去，发现的是**五个各自独立、但症状相同的洞**：

| # | 缺陷 | 用户可见后果 |
| --- | --- | --- |
| ① | 发送前**没有预算门** —— 超长请求直接发出去，等上游报错 | 长会话突然失败，且失败原因看不出来 |
| ② | 引擎侧**没有保险门** —— 只要不报错就一直堆 | 单轮工具调用的输出能撑爆窗口 |
| ③ | **摘要覆盖**只写不算 —— 摘要生成了，但没被真正顶替原文 | 「压缩过了」但 token 数纹丝不动 |
| ④ | 「压无可压」**只给建议**，不给动作 | 用户看到一句提示，然后没有然后 |
| ⑤ | 上下文上限**不跟随所选模型**；且「K」的进制按固定写法推断 | 切了模型，环与右栏的上限纹丝不动；512K 的模型被当成 128K |

五条的修法都不在「多写一段压缩代码」，而在**判据的归属**：

- **预算门**放在发送之前，按**本轮即将发出的真实负载**算，不按历史长度算。
- **保险门**在引擎侧对单次工具输出封顶，超出的部分走摘要而不是直接丢弃。
- **摘要覆盖**从「生成摘要」变成「**替换进消息序列**」，并有断言确保替换真的发生
  —— 这一条是本轮最典型的「看起来在工作、其实一次都没生效」。
- **可救模型**：压缩到极限时不再只提示，而是给出**一键切换 + 续本轮**。
- **窗口随模型**：上限从所选模型推导；「K」的进制**按该行存量值反推厂商写法**，
  不再按固定口径断言。

配套的还有上游 RPM 限流（A-1091 / A-1092）：Agnes 官方下调了 RPM，而应用侧
**没有任何执行者** —— 限流配置是个死开关。现在有四层取值（手填 > 模型 > 供应商 > 全局），
探针实测档位，并把单位陷阱一并处理。

## 二、Agent 输出：引导链路、实时化与「唯一产地」（A-1059 ~ A-1071 · A-1094 · A-1095 · A-1105 · A-1124）

### 1. 引导（steer）与计划接续

引导此前只有一个「已排队」的模糊态。现在拆成**三态**（收到 / 已并入 / 已生效），
计划（`todo_write`）与下一轮之间补上接续判据，阶段标题由引擎按实际动作命名而非回落到占位词。

### 2. 实时化：工具卡、阶段标题、产物、待办

渲染侧此前是「一轮跑完才更新」。现在工具卡有实时态、阶段标题实时生成、
思考产物实时可见、待办全景实时刷新 —— 并且**去掉了面板级定时器**
（它每几秒把整个聊天面板重渲染一次，正是卡顿的典型形态）。

### 3. 流式期表格不再裸露（A-1094）

流式过程中表格的管道符号会裸出来。根因有两处，都在**「行没写完 / 没到齐」的瞬间**，
但两处的**时机不同** ⇒ 必须分两段修，用同一个修法只能治一半。

### 4. 正文后置闸门：两条渲染路径合并（A-1124）

用户的两条反馈 ——「切走再回来，老设定就覆盖回来」与「渐入哪里都没有」——
是**同一个根因**：同一份「本轮正文」原来有**两套互不相干的渲染路径**
（流式现场块、切会话恢复时的占位气泡），后者是**裸渲染、不传流式标记、无闸门**。
切走再切回 ⇒ 旧路径接手 ⇒ 闸门与渐入同时消失。

修法是把闸门 + 渐入 + 占位抽成 **`GatedBody`（唯一产地）**，两条路径共用。

同轮还改掉两处「阶段做完立刻收起」与一个**全局动效开关**：
`prefers-reduced-motion` 此前把思考与正文两处渐入一起关掉且完全静默。
现按 WCAG 2.3.3 口径改成**只去位移、保留不透明度渐入**。

### 5. 子代理弹层的 markdown（A-1105）

子代理弹层的 markdown 渲染失效，根因是**把块级结构当成了行级文本**；
顺带收敛了「碎片换行」的残留。

## 三、设置面板：栏目重排、留白地板、外观（A-1119 · A-1125 · A-1115）

### 1. 左栏按语义分成四组（A-1125）

用户原话：「现在设置栏的菜单排序很混乱，你自己衡量一下各个板块的重要性以及使用频率，
进行综合排序。」

排序依据取了**两条权威口径 + 一份本项目一手证据**：

- **Android 官方设置规范**：栏目数在十几项量级时，用 **2–4 个分组分隔符**，
  重要项置顶、实验性垫底；
- **NN/g《Alphabetical Sorting Must (Mostly) Die》**：字母序在设置类界面里是**最差**的排法，
  应按**重要度或使用频率 + 逻辑结构**组织；
- **本项目一手证据**：代码里有三处**程序化跳转**（跳到状态 / Agent / 供应商），
  以及标题栏齿轮按钮的说明文案点名了四个栏目 —— 这几个是被**反复用到**的。

于是 13 个栏目重排为四组：

| 组 | 含义 | 栏目 |
| --- | --- | --- |
| 常用 | 打开设置最先要动的 | 通用 · 外观 · 权限 · 供应商 |
| Agent 与能力 | Agent 自身的配置 | Agent 管理 · 心智中枢 · 技能库 · MCP · 常驻 |
| 运行与维护 | 看状态、查用量、调环境 | 运行环境 · 使用统计 · 状态 |
| 高级 | 实验性内容 | 实验性 |

分组**只在浏览态显示标题**；一旦在搜索框里输入，结果**平铺**呈现 —— 搜索时用户要的是
「命中了哪些」，不是「它们分属哪组」。空组不画标题（否则会出现一个挂着标题、
下面什么都没有的区块）。

### 2. 留白地板：13 个页面的左缘第一次对齐（A-1119）

用户两次取证：「与边界相交、拥挤」+「顶着标签页」。根因是
**留白是「每页各写一份」的** —— 内容区只有右内边距、没有左内边距，
左侧留白全靠各面板自管，实测口径有 **16 / 12 / 4 / 0 四种**，谁写 0 谁就贴线。

修法是**治本**：把水平地板收归共用祖先（内容区统一给左右内边距），
各面板根一律归零。地板取 16px，正好让原本就是 16px 的七个页面**像素级零变化**。

⚠️ 水平边界是**共用事实**（可以收归祖先），**垂直节奏是各页自己的**（不能收）——
首次只修左右、漏了上下，于是页签顶到了内容区上沿。这一条已显式写进各页。

### 3. 外观：目录卷轴与主题归位（A-1115）

「外观」从「通用」里独立出来，主题选择一并迁入。新增**目录卷轴**：
聊天区与 markdown 预览右侧的一条波形 / 刻度带，指针移动即响应，
位置可点跳转；markdown 页滚动到某条标题时，对应刻度会隆起。
演示框与真身**共用同一个组件、同一份参数**（改设置即时生效且不重挂）。

这一块迭代了十轮，攒下的判据写在这里（都是实测得来的，不是设计直觉）：

- **「两根线」要能被看见，间距必须大于两条描边的覆盖宽度之和**（抗锯齿每边还要 +1px）。
  曾经出现过「两根线全程糊成一条」，用户报「明暗区分越来越小」，
  真相是**当时根本没有两根线** —— 线太细、间距不够。
- **从等距铺的 N 个东西里选一个时，衰减 / 影响范围必须按间距归一，不能按绝对像素。**
  绝对像素只在「被选对象的位置与数量无关」时才成立（鼠标悬停属于后者，
  「当前是第几条」属于前者）。曾按固定像素衰减，条目一多相邻刻度权重就到 0.99
  ⇒ 一次亮三五条且亮度一样 = 用户说的「看不出是哪条」。
- **端部过渡（渐隐 + 收束）必须是渐变的**，两端过渡长度下限不许为 0
  （0 = 端点成一段精确直线，反而「看得见」）。

## 四、右侧栏：从展示区变成工作面板（A-1116 · A-1120 · A-1121 · A-1122 · A-1123）

### 1. HTTP 工具能产出任意多文件的 web 程序（A-1116）

此前只能落 6 个固定模板文件。现在可以传**任意多文件**（路径 + 内容），
路径做**收敛而非清洗**（拒绝绝对路径 / 盘符 / 上跳，不做「清洗后再写入」——
清洗会造成**假成功**）。工具描述也写清了「做成什么样才算好」：
自包含、不引外网 CDN、能交互、像样的视觉、零构建。

回执里列出**真实写入清单**（此前写死成模板名，是假陈述）。

### 2. 网页预览（A-1120）

产出的本地页面可以直接在右栏打开预览。

### 3. 终端与文件树的程序化开关（A-1121）

把右侧栏的 opener 从「只能开浏览器」扩成**通用 payload 化入口**，
Agent 可以开终端、开文件树。这是「右侧栏 = 工具面板」这条设定的接线。

### 4. 产物文件改动可回滚（A-1122）

产物改动有了**撤销**能力，并配一份可读的改动回执。

### 5. 屏幕控制补上「命中校验」（A-1123）

用户要求：点按钮后回执里要能看到「命中校验」，未命中**自动重试一次**。

判据是动作前后两张截图的**像素差异率**，并刻意分成**三种**：

- **没有判据**（未装配度量 / 参考图没取到 / 两张图不可比）⇒ 判「未判定」，
  **算通过、不重试** —— 「没法判定」和「判定为失败」是两件事，
  混在一起会让每一次都在无意义地重试；
- 差异率 ≥ 0.2% ⇒ **命中**；
- 差异率 < 0.2% ⇒ **未命中** ⇒ 原样重试一次后重判。

回执统一成一行「命中校验：✓ 命中 / ✗ 未命中 / 未判定」，未命中附可操作的下一步。

## 五、子代理：授权、模型池、临时定义（A-1096 ~ A-1114）

- **三态授权（A-1096）**：子代理的授权不再是布尔量，而是三态，
  且「授权」与「模型选择」分离。
- **执行模型池（A-1097 / A-1098）**：可为子代理指定执行模型；
  模型池的**草稿态与已保存态分离**（此前共用一个 state，
  于是勾选会被下一次重渲染悄悄取消）；浮层用**实底**而不是半透明卡片。
- **临时子代理（A-1114）**：派发时可以**现场定义**（给名字 / 系统提示 / 工具集）。
  这种定义**不落盘、不进清单、不参与路由匹配、跑完即弃**。
  顺带堵掉两个真洞：① 内联工具集此前**原样直通**，带上派发工具就能绕开深度守卫；
  ② 产物文件名第一次由模型决定（`a/b` 会 ENOENT、`..` 会逃逸），
  现由**唯一出处**的文件名收敛函数处理，且**只改文件名、日志里保留原名**。
- **保存按钮无效（A-1103 / A-1104）**：根因是**两个字符** ——
  自执行异步函数少了尾部的调用括号，于是「点了没反应、弹层不关、值不落盘」。
- **全局降级池（A-1108）**：`A-1108` 建立全局降级池，**默认必须是空的**
  （有默认值就等于悄悄改变了用户没选过的行为）。

## 六、系统集成与界面细节

### 1. 通知身份注册（A-1102）

自 A-1055 起通知图标身份**每次启动都在静默失败**。根因在注册字段与 URI 构造，
现在使用**安装根**取图标、文件不存在就交给系统兜底而不是塞一个坏路径。

### 2. 系统执行权限（A-1101）

「命令窗口全是 error」定责为三层，逐层修 —— 不再把三层混为一谈。

### 3. 任务栏 / 托盘图标（A-1075）

改为**按渲染尺寸预置多尺寸 ico**，全程零缩放。

### 4. 自定义调试端口（A-1110）

调试端口不再硬编码，取实际监听端口并落盘到可读文件。

### 5. 滚动条统一（A-1113）

全应用**唯一一份**滚动条样式（6px 全圆角胶囊 / 轨道透明 / 静止与悬停两档透明度）。
⚠️ 这里踩了一个静默失效：Chromium 121 起 `scrollbar-color` / `scrollbar-width`
**优先级高于** `::-webkit-scrollbar-*`，写了就整块忽略、静默回落平台默认
（Windows 上是约 15–17px 的灰条）—— 恰好是用户报的「滚动条又粗又丑」。

### 6. 侧栏拖拽接缝（A-1117）

用户先报「发光覆盖在边界线上、臃肿」，于是删掉了柔光带；
紧接着报「太窄了，怎么这么细」—— 因为**删掉的那份可见性没人接住**。
正解是**让线本身变粗**：多出来的部分**向内**画，视觉 3px，**零布局位移、
零覆盖元素、仍然只有一个产地**。

### 7. 上下文气泡的滚动跟随与呼吸灯（A-1107 / A-1108）

锁滚手感重做（`scrollFollow`），呼吸灯从「频闪」改为合成器驱动 ——
根因是它动的是背景色（每帧主线程重绘），改成动不透明度与变换后，主线程忙也平滑。

### 8. 分隔条流光与命中区（A-1106 / A-1109）

「过一会自己变样」、「命中区更窄」两类问题都归到**静默失效家族**：
改了不报错、只有用户在自己机器上看得见。同轮把市场（MCP 广场 / 技能广场）
的中文化收归**唯一判据出处**。

  测试确实红了、但红的不是那条判据 ⇒ **假绿**。
