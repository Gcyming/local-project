## 本版重点

**启动更快、操作更"看得见"、控制台干净了。**

这一版主要处理三件用户能直接感知的事：① 启动后左侧会话列表长时间空白；
② Agent 操作界面时，用户点击 slime 内一些地方会失效、要重按；③ 调试控制台每次冷启动刷一屏报错。
另外把右栏浏览器从"进去一片纯白"改成了跟随 slime 主题色，并继续给安装包瘦身。

## 一、修复

### 1. 启动后左侧会话列表长时间空白（A-1043）

**现象**：打开应用后左栏长时间空着，像全新安装。

**根因**：会话列表与 Agent 列表的取数被挂在整条初始化链**后面**，且 `await` 了重活；
并发调用还会各跑一遍整条链（首屏被整条初始化挡住）。

**修法**：

- 两个列表退回**轻量注册表**立即返回，重活改为启动期后台预热（不再 `await`）
- 初始化链加**单飞**（并发调用共享同一次初始化，不再 N 遍重跑）
- 单飞**失败不缓存**（一次瞬时失败不会永久废掉初始化），成功后保持 inflight 不失效

**守卫**：`tests/gui/a1043-guards.spec.ts` 17 条；变异 `mut-a1043-startup.mjs` **11/11 捕获**。

### 2. Agent 操作与用户点击冲突（"点哪都要重按"）（A-1044）

**现象**：Agent 操作右侧栏 / 我的主机时，用户点 slime 内的地方会失效，要重新点。

**先说结论：Windows 上没有"偷偷注入输入"的合法隔离通道** —— Agent 与用户共享同一套物理指针、
前台窗口和焦点。参考主流 Agent 的做法后，范式定为 **让位 + 串行 + 可见化**，而不是抢。

- **让位**：动作执行前用系统级空闲探测（`GetLastInputInfo`，无需 hook / 管理员权限）判断用户
  是否正在操作；用户在动 → 等待，超过预算 → 中止。探测不可用时**放行但留痕**（"探测不到"≠"用户空闲"）
- **可见化**：被操作的界面加**呼吸灯边框** + 可主动隐藏的悬浮提示（浮层不吃点击，
  动画只动 `box-shadow` / 边框色，不逐帧触发布局）
- **焦点归还**（应用内"点击被吞"的直接成因）：`webview.focus()` 会抢走焦点并触发滚动，
  把用户正要点的目标移走。改为 `focus({ preventScroll: true })`，且**仅当焦点仍停在 webview 上**
  才在动作结束后把焦点还给用户

**守卫**：`a1044-guards` 两份共 44 条；变异 `mut-a1044-inputarb.mjs` **23/23 捕获**。

### 3. 冷启动控制台刷屏：`No handler registered`（A-1048）

**现象**：每次启动刷一屏
`Error occurred in handler for 'slime:resident:state'` / `'slime:requests:get'`。

**根因**：这两个通道的 `ipcMain.handle` 被写在**惰性初始化** `ensureServicesOnce()` 里，
而渲染层从窗口创建就开始轮询 —— 服务初始化要等技能扫描 / 调度器 / SILAM 一串重活（实测好几秒），
这段时间每次轮询都抛错。

**修法**：通道**在启动时注册**，值改为惰性提供 —— `resident:state` 走"提供者"
（就绪前返回空态，就绪后换真实现）；`requests:get/set` 本来就只读一个本地 json，
与调度器毫无关系，一并移出。

顺带修掉两处同源问题：

- **后端"假降级"**：Python 后端 10 秒未就绪就**永久**标记"可用性受限"且不再重试。
  Windows 上 Python 首次导入（工具 / 技能 / A2A 一串 import）经常超过 10 秒 →
  明明起来了却显示降级。改为先报"仍在启动"，后台继续探最长 50 秒，就绪即升回正常
- **技能目录缺失日志刷屏**：同一路径每次刷新都报，改成**只报一次**

**守卫**：`tests/gui/a1048-guards.spec.ts` 8 条；变异 `mut-a1048-bootipc.mjs` **7/7 捕获**。

### 4. 权限 / 提问被静默丢弃（A-1047）

**现象**：偶发"好久没看见提问"、Agent 卡住不说话，界面上却什么都没有。

**根因**：权限请求与 ask_user 提问各有一句 `if (reqSid !== sessionRef.current) { return; }`，
**丢弃是静默的** —— 控制台一行不写、界面一点不动，而主进程那边还在等回答（超时 300 秒）。

**修法**：判据抽成唯一实现（`gui/src/renderer/pages/requestOwner.ts`，两处共用），丢弃**双重留痕**：
① 可 grep 的统一前缀日志；② **立刻回一个决策**（提问回"跳过"、权限回"不批准"且绝不 `alwaysAllow`），
让主进程马上放行而不是干等。

**守卫**：`tests/gui/request-owner.spec.ts` 13 条；变异 `mut-a1047-reqowner.mjs` **7/7 捕获**。
链路探针 `assert-ask-chain.cjs` **5/5 通过**（`mismatch` / `noguard-nosid` 现在如实显示"留痕 1 条"）。

### 5. 发布说明显示成 HTML 标签源码（A-1042，v0.0.4 的锅）

v0.0.4 的 Release 正文被手写成 HTML，而**客户端永远落后一版** → 老客户端必然把标签源码当成正文原文显示。

- 修复在 v0.0.4 就已进源码，但**那个包装在修复之前** → 本版才会真正生效
- 治本：发布说明**正本**改为仓库内受版本控制的 `docs/releases/v<版本>.md`（Markdown 是三方都能吃的
  最小公分母：GitHub 原生渲染、本项目解析器认、**旧客户端也能当可读文本**），打包目录里的同名文件降级为副本

## 二、优化

### 1. 右栏浏览器页跟随主题色（A-1045）

进浏览器页是一片纯白、很晃眼。根因是 `<webview>` 的 guest 文档（含 `about:blank` 占位）由
Chromium **白色基底**绘制，宿主 CSS 管不到 guest 内部。三处一起堵：宿主层与 webview 底色改用主题变量、
加**不透明**主题色占位页（不吃 Agent 的点击）、地址栏随主题（不再近黑底）。

### 2. 安装包继续瘦身：LanceDB 改为"内嵌组件"（A-1041）

- 默认安装包**不再**内联 297 MB 的原生模块（`out/main` 实测 2.9 MB）
- 能力**不砍**：组件就位即用（随包目录或应用内下载），未就位时**如实提示降级**，不静默
- 本版补齐"完整版随附"的打包配置（`electron-builder-full.json`），并用守卫锁死
  **打包目标路径 == 运行时候选路径** —— 这两处一旦漂移，就是"体积付了、界面永远提示未就位"
- 端到端探针 `probe-lancedb-component.mjs` **7/7**（真的加载 293 MB：连接 → 建表 → 写入 → 查回）

### 3. 测试稳定性

`import.spec.ts` 在全量并发下偶发 5 秒超时。根因是默认实现会拉起 297 MB 原生模块
（单跑命中缓存只要 663 ms，并发抢磁盘时被掐）。修法是**逐调用点显式注入依赖**，
不是加超时；并加了守卫防止后续新增用例把重活带回来（`a1046-guards` 4 条 / 变异 4/4）。
