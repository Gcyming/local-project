## 本版重点

**技能真正能用了、等待变成"看得见"、并且可以边跑边插话。**

这一版处理三组用户能直接感知的事：① 技能库相关的一串静默故障（全新安装技能库为空、
第三方技能描述显示成 `--`、Agent 把技能写到了看不见的地方）；② Agent 半天不输出正文时
界面上毫无反馈；③ 几条真机使用中发现的缺陷（切会话后永久停在「恢复中」、巨型蓝色气泡、
diff 卡片配色）。

## 一、新增能力

### 1. 输入框上方的「实时状态行」（A-1054）

**动机**：Agent 经常一段时间不吐正文，但右栏活动记录还在增长 —— 界面等于没有反馈，
不知道它在思考、在调工具、还是在等自己回答。

在输入框上方新增一条**跟随模型当前阶段**的状态文本（沿用项目既有的扫光样式）：

- 按优先级如实推导当前阶段：**等审批 / 等回答 → 压缩上下文 → 停止中 → 写正文 → 调工具 → 思考 → 准备中**
- 细节随阶段变化：已用时（跨分钟补零，如 `3m04s`）、token 估算、工具名 / 当前动作
- **等用户输入时不播扫光** —— 这一条是刻意的：如果模型其实在等你点确认，还在播"运行中"的
  扫光会让你干等，比不给提示更糟
- 判定逻辑抽成纯模块 `liveStatus.ts`（不含 JSX），可测、可变异

### 2. 中途插入 / 即将插入指令（A-1054）

生成过程中依然可以下指令，两种模式，位置也在输入框上方：

- **排队（默认）**：指令入队、**不打断**当前回复，本轮结束后按先进先出自动发出
- **打断**：立即中止当前流，把这条指令换成新的提问

配套：待发指令以面板列在输入框上方，每条可**单独切换插入方式**、可删除、可提升为下一条；
工具栏在生成中显示模式切换按钮，鼠标用户也能插入。

队列语义（写进纯模块 `instructionQueue.ts`）：先进先出、**跨会话隔离**（只认队首且 sessionId
匹配，杜绝把别的会话的指令发到本会话）、身份用自增 id 而非下标；图片随指令一并入队，
不再依赖容易被串掉的共享待发态。默认不打断（非破坏性一侧）。

**守卫**：`a1054-guards`（44 条，含接线与单一起源地）+ `a1054-queue`（20 条）+
`a1054-livestatus`（21 条）；变异 `mut-a1054.mjs` **35/35 捕获**。

### 3. 默认技能随安装包（A-1050）

**根因**（拆开已发布的 `Slime Setup 0.0.5.exe` 取证，不是推理）：打包配置里**没有**
`config/skills`，而 `config/` 整个目录被版本控制忽略 → **全新安装的技能库是空的**，
而默认工具档案引用的 6 个技能在盘上根本不存在，白名单被**静默**解析为空。

**修法**：技能正本迁到受版本控制的 `gui/template/skills/`，首启播种到用户目录：

- **不覆盖**用户已有同名技能
- **不复活**用户删掉 / 停用过的技能（台账只记「真的复制成功了」的名字 —— 记账记了没做过的事，
  用户删掉自己那份就再也补不上）
- 幂等；只在**打包版**播种，开发版刻意不播（避免把「打包漏配」这类只该在打包版暴露的故障悄悄补上）

**守卫**：`a1050-guards` 11 条；变异 `mut-a1050-skillseed.mjs` **7/7 捕获**。
`--dir` 实物验收：`template/skills` 10 目录 / 71 文件与源一致，6 个声明默认技能 6/6 带 SKILL.md。

## 二、修复

### 1. 第三方技能描述读不出来（A-1049）

**现象**：技能库里 6 个技能描述全是 `--`、状态显示「manifest 缺失 · SKILL.md 有」。

**根因（两个产地，同一病因）**：校验层自研的简化 YAML 解析器**不支持块标量**（`>` / `|`），
而这些 SKILL.md 用的正是 `description: >`（多行折叠）→ 旧实现把**字面量 `>`** 当成描述存了下来；
界面层在缺清单时取 SKILL.md 的**物理首行**，而带 frontmatter 的首行就是分隔符 `---`。

**修法**：解析器补块标量（含缩进回退即块结束）；抽出**共享**的 frontmatter 描述提取供两层共用
（各写一份必然漂移，这正是本次的形态）；界面层的"取首行"先剥 frontmatter 再找标题。

**守卫**：技能校验与界面模块两处共 6 条，两条变异都精确变红。

### 2. Agent 把技能写进了看不见的地方（A-1049）

**现象**：Agent 报告"写入文件成功"，但技能库永远看不到。

**根因**：系统提示里只有**相对写法** `config/skills`，Agent 就写进了源码仓库，
而打包版读的是用户目录 —— **两侧都不报错**，文件真的写成功了。

**修法**：技能根目录收敛为唯一实现，提示的**两个分支**都下发**绝对路径**、明确劝阻写到别处、
并要求写完用技能检索复核。变异（空名单分支漏下发）精确变红。

### 3. 「切换会话后永久停在（恢复中…）」（A-1051）

三个独立成因叠在同一条路径上，**都不报错**：

- 查询失败被吞成"仍活跃"，与正常分支走同一个出口 → 一次失败即**永久卡死**
- 可选链写漏一层，方法缺失时直接抛错、无人接管 → 结束 loading 永不执行
- 结束 loading 被绑在一个与它无关的"粘性"标记上 → 标记残留后每次切回都跳过

**修法**：判定抽成纯函数 `resumeOutcome.ts`，**用签名消灭第二类错**（入参里根本没有"用户是否点过停止"）；
查询失败改为**有上限的重试**；并补上遗漏的状态复位（该残留还会污染之后新流的错误处理 ——
把真实错误当成"用户主动停止"，静默跳过自动重连）。

其中一条判定是**刻意的取舍**：重试耗尽后既结束"恢复中"（没证据支撑流还活着，不该让用户无限等），
又**不删气泡、不打判死标记**（也没证据支撑流已死）。

**守卫**：`resume-outcome.spec.ts` 17 条；变异 `mut-a1051-resume.mjs` **19/19 捕获**。

### 4. 「巨型蓝色气泡」：连续空行各撑成一整行（A-1052）

**现象**：正文只有两句，气泡却高 646px，中间约 630px 纯空白。

**取证**（截图不可直读 → 逐像素取色 + 几何测量 + 解包比对运行产物）：色值与主题变量**逐字节相同**
（排除配色）、宽度命中常规用户气泡容器、头像列为空（排除角色错配）。
**根因**是正文容器用了预格式化空白 —— **连续空行每行各占一整行高度**。

**修法**：新建 `messageText.ts`，把**连续空行**收敛（只折叠连续空行，绝不合并单换行 ——
用户粘贴的多行日志单换行有意义）；接入三处渲染点，而**复制 / 回滚 / 发送一律保持原文**。

**守卫**：`message-text.spec.ts` 17 条；变异 `mut-a1052-blank.mjs` **16/16 捕获**。

### 5. 侧栏品牌图标是字母「S」，不是应用图标（A-1054）

品牌位此前是一个写死的字母「S」。改为引用应用图标资源，并把该资源的引用收敛为唯一出处。

### 6. 切回会话时正文要等很久才出来（A-1054）

**根因**：思考面板的"展开 / 收起"是**常驻挂载 + 切类名**（收起只是裁切，子节点仍然在），
于是**收起状态下也在整块计算思考时间线**，纯属白工。

**修法**：改成**首次展开才计算并挂载**（懒挂载），并保留展开动画所需的**两帧提交**
（第一帧挂载、类名仍收起，第二帧再切换）。决策抽成纯模块 `reasoningGate.ts` 以便被行为断言 +
变异锁死，避免又变成无测试覆盖的内联逻辑。

### 7. Agnes / 小红书 上下文显示成「524K」（A-1049 + A-1054）

**结论先行：探针没坏，也不是上游故障 —— 是内置表这一个值本身的口径写错了。**

项目全部的 K 显示口径是**十进制**（`÷1000`）。厂商官方文档自己就把窗口写成 **512K**，
而表里存的是 `524288`（= 512×1024，二进制）→ ÷1000 之后界面读成 **"524K"**，
与官方写法、与注释、与用户设置三处全对不上。

修法：表内改为 `512000`（与同一张表里其余头条模型一致：`gpt-4o 128000` / `claude 200000`）。
**不是**改显示层 —— 显示层口径是全项目统一的，为一个模型改它会把别的模型一起改坏。

> 为什么 Kimi / Doubao 保留 2 的幂（`262144`）：那两家的官方文档**自己就把 K 定义成 ×1024**
> （如"最大输出长度是 256×1024 − prompt"），所以 `262144` 对它们是**忠实值**。
> **判据是"厂商怎么定义 K"，不是"我们偏好哪种数制"。**

顺带说明一件被反复问到的事：**上游对部分模型不发布价目是常态，不是我们的故障**；
表内 `agnes-2.5-flash` 现价为 `0` 是**正确**的 —— 该档官方**限时免费**（刊例价非 0），
"显式 0"（免费）与"未定价"在我方语义里本来就不同。

## 三、优化

### diff 卡片 +/- 配色与主题不一致（A-1051）

同一屏上，思考历程里的增删行取主题变量（跟随主题），而产物卡的变更详情**写死了十六进制**，
于是两处绿红对不上、切主题时一处变一处不变。改为统一取主题变量（保留兜底值），
并加守卫锁死「两套主题都定义了全部 diff 变量」—— 防止变量名打错导致静默回退、切主题失效。
