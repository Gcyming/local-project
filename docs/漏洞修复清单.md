## 阶段 1 — P0 止血（功能全毁 / 幻觉根因，改完立即有效）

### P0-1 流式工具循环悬空（多轮工具链失效）
- **位置**：`core/llm.py:711-715`（`_handle_tool_calls_stream`）
- **现象**：`for round_no in range(1, _TOOL_MAX_ROUNDS+1):` 的循环体只有 `details: list = []` 一行，`async for item in _execute_tools_with_progress(...)`（715 行）及后续二次请求、`if not next_calls`、`pending = next_calls` 全部在**循环外**。实际只执行 1 轮工具；模型第二轮再要工具时永不执行，直接打"已达上限"（782 行）；且 `round_log.append((round_no, details))`（720 行）的 round_no 恒为 3，日志谎报"第3轮"。
- **影响**：流式对话（CLI 主通道）多轮工具链（web_search→web_fetch→生成）断链 → 模型编造结果。幻觉放大器。
- **修复**：把 715-783 行整体移入 for 循环体（保持缩进正确），`round_log.append` 放循环内；超限日志（782）保持在循环外。
- **验证**：CLI 发"查一个词的定义并保存到文件"（触发 ≥2 轮工具），观察 tool 事件 ≥2 批；`py qa.py`。

### P0-2 多进程 swarm 全毁（NameError）
- **位置**：`core/executor.py:234`（`_run_multiprocess`）
- **现象**：`_mp_to = _resolve_task_timeout(plan, bool(video_subs))` 引用 `video_subs`，该变量只在 `_run_async`（L553）定义。多进程路径 NameError 被外层 except 吞掉 → **所有多进程 Worker 必失败**（"执行异常: name 'video_subs' is not defined"）。
- **影响**：`/task`、`/auto` 的 multiprocess 模式（分裂/多 Agent 并发）整体不可用。
- **修复**：本函数内先计算：`video_subs = [st for st in plan.subtasks if _is_video_generation_task(st)]`（对齐 L553 写法）。
- **验证**：`/auto` fork 任务（max_workers=2）真实并行出结果。

### P0-3 filter 误过滤技术标识符（污染源头）
- **位置**：`core/filter.py:52-57`（`\b(Agnes|...)\b` 替换规则）、`filter.py:130`（`_IDENT_RE`）
- **现象**：
  - `\bAgnes\b` 词边界在连字符后成立 → `agnes-image-video` → `slime 平台-image-video`；裸域名 `platform-outputs.agnes-ai.space`（无 scheme）同样被破坏
  - `_IDENT_RE`（`\b(agnes-[a-z0-9.-]*[0-9][a-z0-9.-]*)\b`）**要求含数字** → 不含数字的 agnes-* 标识符全部漏遮蔽
  - 同族命运不一致：`agnes_generate_image`（下划线，\b 不切分）幸存
  - 部分匹配残片：`gpt-4o-mini` → `slime 平台o-mini`、`Claude-3.5-sonnet` → `slime 平台-3.5-sonnet`（filter.py:46-51 规则只匹配品牌词本身）
- **影响**：模型从过滤产物（历史/记忆/行为）学到错误技能名 → skill_lookup 失败 → 编造。全部污染闭环的源头。
- **修复**：
  1. `_IDENT_RE` 改为保护**所有** agnes-* 连字符/点标识符（去掉 `[0-9]` 硬性要求，如 `\b(agnes-[a-z0-9._-]+)\b`）
  2. 品牌词规则改为"整词+连字符后缀整体替换"（先遮蔽整个 token 再还原，杜绝残片）
  3. alternation 补裸名：`GPT`、`gpt`（filter.py:46-51/72-83）
  4. 同步更新 `tests/test_smoke.py`（`test_filter_agnes_model_name` / `test_prose_agnes_still_filtered`：品牌提及仍过滤、技术标识符还原的语义边界）
- **验证**：`test_prose_agnes_still_filtered` 类用例 + 新增"技能名 agnes-image-video 不被替换"用例。

## 阶段 2 — 断污染（学习管线 / 护栏）

### P1-1 全学习管线以"过滤后文本"为输入

- **验证**：删除记忆后对话 3 轮含技能名，查 memory.json/behavior.json 无 "slime 平台" 字样。

### P1-2 success 判定黑名单漏判（失败当成功）
- **位置**：`slime_server.py:865-867`（/chat）、`1252-1255`（流式）
- **现象**：`[工具调用处理失败`、`[工具调用后请求失败`、`[工具调用轮次已达上限`、`[工具调用后无文本回复`、`[本地模型加载失败/未就绪/调用失败`、`[Agent 未返回有效回复]`、`[委托失败`、追加的 `[截断]` 均不在失败排除列表 → success=True 入库并驱动人格/情绪演化（编造正反馈）。
- **修复**：黑名单补全上述前缀；`[截断]` 标记的回复强制 success=False；error 事件与 full_reply 并存时（L1248 `reply = full_reply or error_msg`）优先 error。
- **验证**：构造工具失败轮次，查 history.jsonl success 字段为 false。

### P1-3 claims 幻觉护栏不核验数值
- **位置**：`core/claims.py:16-45`（触发词/扩展名白名单）、`45-87`（只核验路径存在性）
- **现象**：
  - 声称"文件大小 1,034,594 字节"指向**真实存在**的文件即通过 → 假字节数/时长/尺寸无法拦截
  - 触发词缺："保存成功/文件位于/输出到/写入完成/上传成功/任务完成/下载地址"；`任务ID: T-xxx`（无扩展名）永不匹配
  - 扩展名白名单缺 `.zip/.docx/.xlsx/.pdf/.html/.mp3/.wav/.webm/.mov/.svg/.db`
  - 在**过滤后文本**上核验 → 真实路径被改写导致误报；`_DOMAIN_FRAGMENT_RE` 豁免"平台.cn/…"残片 → 编造 URL 残片被豁免（A-050-R 是掩盖根因的补丁）
  - 域名残片 TLD 白名单缺 `.jp/.de/.uk/.dev/.app/.net.cn`
- **修复**：① claims 增加数值核验（对声称的字节数/时长，用 file stat 比对真实值）；② 补触发词与扩展名；③ 核验在**原始文本**上进行。
- **验证**：构造"生成成功 + 假字节数 + 真路径"回复，护栏应报错。

### P1-4 轮次耗尽摘要未过滤进历史
- **位置**：`core/llm.py:691-692`（非流式）、`783`（流式）
- **现象**：`_format_tool_rounds(round_log)` 含工具名/args/结果原文，不过 `_apply_filter` 直接作为回复入库。
- **修复**：两处返回前过 `_apply_filter`；或在 server 层统一过滤。
- **验证**：工具轮次耗尽的回复入库后无品牌名泄漏。

### P1-5 psyche 注入无预算 / 记忆内容污染
- **位置**：`core/llm.py:414-428`（`_inject_psyche` 在截断后追加）、`223-232`（记忆来源为过滤产物）
- **现象**：心性上下文可达 `max(512, max_context*0.3)`，超出 max_context 30%+ → context-overflow 错误串再入历史（二次污染）；`context_budget <= 0` 时回退整个 max_context 而非 512（与本地路径 L969 语义不一致）。
- **修复**：psyche 注入纳入预算计算；≤0 时下限 512；记忆提取断源（P1-1 修复后自然解决）。
- **验证**：小 max_context（如 2000）对话不触发 overflow。

## 阶段 3 — 安全加固

### P1-6 敏感名单大小写敏感（Windows 绕过）
- **位置**：`tools/builtin.py:37-38, 97, 169`
- **现象**：`{".slime_pass", "providers.enc.json", "auth_token.enc", "auth_token.json"}` + `p.suffix == ".enc"` 均小写；Windows 大小写不敏感 → `AUTH_TOKEN.JSON`/`.SLIME_PASS`/`PROVIDERS.ENC.JSON` 变体绕过 file_read/file_write 拦截 → 读取认证令牌/passphrase（解全部 provider key）、覆写 auth_token 植入后门。
- **修复**：名单比对统一 `name.lower()`；`p.suffix.lower()`。
- **验证**：新建 `AUTH_TOKEN.JSON` 副本，file_read 应拒绝。

### P1-7 file_write 可写关键文件（提权/RCE 链）
- **位置**：`tools/builtin.py:148-183`（A-041 仅限项目根内）
- **现象**：项目根内可写：`config/agents.json`（注入 sandbox_override 全权限）、`slime.toml`（改 api_base/MCP → 密钥外发）、`core/*.py`/`tools/*.py`（重启后 RCE）、`data/audit.jsonl`（审计灭迹）。
- **修复**：写入黑名单：config/、core/、tools/、slime*.py、*.toml、data/audit.jsonl、*.enc、.slime_pass；或改白名单（仅 data/ 与指定输出目录）。
- **验证**：file_write 写 slime.toml 应被拒。

### P1-8 拒绝路径零审计
- **位置**：`core/sandbox.py:607-612`（`check_permission` 不记录）、`core/llm.py:541-552`、`slime_server.py:1707-1709`
- **现象**：审计只在 `grant_permission`（允许时）发生；所有被拒操作不留审计 → 攻击尝试不可见。
- **修复**：`check_permission` 拒绝分支写审计（或 LLM/API 层拒绝时统一 record_violation + 写审计）。
- **验证**：触发一次拒绝，data/audit.jsonl 出现 status=denied 记录。

### P1-9 mcp_* 通配自动批准使权限声明失效
- **位置**：`slime.toml:69`（`auto_approve_tools = [..., "mcp_*", ...]`）+ `core/sandbox.py:657`（工具匹配优先于等级判定）+ `core/mcp_client.py:934-949`（MCP 工具缺省 network）
- **现象**：任何 MCP 桥接工具无视声明权限自动批准（network 权限 L4 本应需确认）。
- **修复**：收紧为具体前缀（`mcp_browser_*` 等）或按 server 名枚举；保留 `tool_permissions` 覆写能力。
- **验证**：新增一个高权限 MCP 工具，未经名单时应弹确认/拒绝。

### P1-10 inject_provider_keys 全量注入第三方子进程
- **位置**：`slime_server.py:254-281` + `core/mcp_client.py:96-105`（browser_use，slime.toml:191 启用）
- **现象**：全部解密 provider key 注入第三方 MCP 子进程 env；未知 provider 用 `env.setdefault("OPENAI_API_KEY", ...)`（L279-280）——多个未知 provider 只注入第一个，其余静默丢失。
- **修复**：仅注入该 MCP 所需的最小 key（白名单映射）；多个未知 provider 报错而非静默丢。
- **验证**：browser_use 子进程 env 仅含指定 key。

### P1-11 未知权限默认 L2 而非 fail-closed
- **位置**：`core/llm.py:539-540, 556-557` + `tools/registry.py:38` + `slime_server.py:1702-1704`
- **现象**：`perm_level_map.get(perm, 2)` 未知权限映射 L2（write）；与 `skill_engine.py:287`（未知权限取最大值）策略相反。
- **修复**：统一 fail-closed（未知权限取最高级）；`Tool.permissions` 构造时校验合法集合。
- **验证**：注册带未知权限名的工具，沙箱按最高级判定。

### P1-12 reasoning 通道零过滤（身份铁律绕过）
- **位置**：`core/llm.py:1126-1129`（流式主循环）、`751-753`（工具轮内）
- **现象**：`show_thinking=on/auto` 时思考内容原样 yield（"我是 GPT-4o 的内部推理"直给用户）。

### P1-13 error 串泄漏 API URL

### P1-14 工具重复执行无去重
