**执行中发现并修复的问题**（详见 REVIEW_AGENT.md A-116）：

1. **生成器 pattern 丢失（契约双端语义分裂）**：agent_id 的 pattern 只进了 zod（.regex），pydantic 无约束 → invalid fixture 在 Python 侧通过 → 修生成器为 `Annotated[str, Field(pattern=...)]`
2. **null vs 缺失双端分歧**：fixtures 里 `error: null`——zod `optional()` 拒绝 null、pydantic 接受 → 契约语义定为"缺失或 string"，fixtures 同步
3. **pnpm 11 在 child_process 非 TTY 下吞输出且返回非 0**（两次踩坑：vitest/build）→ contract-check 与冒烟统一直调二进制（node node_modules/vitest/vitest.mjs、node node_modules/typescript/bin/tsc）
4. **TS 参数属性超出 strip-only 模式**：node 直跑 .ts 失败 → UpstreamError 改显式字段赋值（兼容 tsc/vitest/node 全运行时）
5. **llama-server 就绪判定**：/health 200 早于模型加载完成（请求 /v1/chat/completions 仍 503 "Loading model"）→ 改轮询 /v1/models
6. **限流测试隔离**：共享实例被前序用例耗尽额度 → 限流用例拆独立实例

- vitest **67/67 passed** 无告警；`pnpm typecheck`（tsc strict + noUnusedLocals）干净；`pnpm -r build` 通过

**目标**：本地（sidecar/llama-server）/ 云端统一路由 + OOM 降级链；Node 会话接真实本地模型流式；同一会话切换本地/云端身份输出不变。

**关键决策**：

- **流式降级边界（诚实协议）**：仅"请求建立前"失败可降级；首个 chunk 之后中断 → 抛错不降级（避免静默切源造成内容重复/丢失）
- **降级记录语义**：`fallbackLog` 只记实际降级事件（4xx 中断不记）
- 原项目语义对齐：model_choice 三选一（inherit/api/local）抽象为统一路由表；VRAM 预算拒绝（503 local_model_error）即 OOM 降级触发点
