## 阶段 9｜自动更新/依赖图标/思考实时显示/安装包自启与卸载/上下文圆环 — ✅ 完成（2026-08-21）

**背景**：用户反馈 5 个问题：① 自动更新一直显示"检查失败: net::ERR_CONNECTION_CLOSED"；② 部分依赖下载完后文本显示"已下载"但左侧图标仍 ❌；③ 思考过程无法展开并实时显示；④ 安装包点"完成"启动 Slime 后又弹开机自启询问（时机错误），且无卸载入口、设置里无自启开关；⑤ 聊天面板右上角加实时加载圆环显示上下文消耗占比（参考 A-C-C）。

**五问题修复（源码核验 + 编译产物 rg 双确认）**：

1. **自动更新检查失败**：
   - 根因：electron-updater 硬编码指向不存在的私有 GitHub 仓库（Gcyming/local-project），每次检查必报 ERR_CONNECTION_CLOSED。
   - 修复：`slime.toml` 新增 `[update]` 段（`enabled` + `feed_url`），**默认 `enabled=false` 不发起任何网络请求**；`mind_config.ts` 新增 `readUpdateConfig()` 解析；`updater.ts` 未启用时状态为 `disabled` 静默跳过，启用后支持自定义 generic feed 或回退 github publish 字段；`StatusPanel` 显示"自动更新未启用（可在 slime.toml [update] 段配置 feed_url 后开启）"。
2. **依赖图标状态不更新**：
   - 根因：`MindHubPanel` 的依赖状态（cfg.deps.ok）只在挂载时加载一次，下载完成后左侧 ✅/❌ 图标停留旧值。
   - 修复：新增 `useEffect` 监听 `dlMap` 下载完成（state==="done"）→ 立即 + 延迟 2s 各刷一次 `configGet`（bge 归位同步、llama 解压+改写 llama_bin 异步，双刷覆盖两种时序）。
3. **思考过程无法实时显示**：
   - 根因：`engine.ts` 的 async generator 无法在流式回调内 yield，旧实现把 chunk/reasoning 全部缓冲，等整段流结束才统一回放 → 思考过程不可见。
   - 修复：改为「后台任务 + 队列轮询」桥接——`router.chatStream` 回调把 chunk/reasoning 边到边推入 `liveQueue`，生成器以 30ms 粒度轮询队列边到边 yield；尾部 StreamFilter 32 字符窗口 flush 后收尾。全链路核验：engine → chat.ts（emitChunk 透传 reasoning）→ IPC（toStreamChunk 保留 type/content）→ ChatPanel（reasoningTmp 实时渲染「正在思考」折叠区）。
4. **安装包自启时机 + 卸载 + 设置自启开关**：
   - 根因：自启询问页挂在 `customHeader`（在完成页之后声明）→ 表现为"点完成启动后弹窗"。
   - 修复：`installer.nsh` 改用 `customPageAfterChangeDir`（选择安装目录后、开始安装前弹自启复选框）；卸载宏清理 HKCU Run 项并询问是否删除用户数据；`!pragma warning disable 6010` 抑制卸载器编译期误报（electron-builder -WX 视警告为错误）。
   - 设置新增「通用」专栏（`GeneralPanel.tsx`）：开机自启开关（`app.setLoginItemSettings`）+ 卸载按钮（定位 `Uninstall Slime.exe` 启动并退出应用）；`index.ts`/`preload` 新增 `slime:settings:autostart:get/set`、`slime:settings:uninstall` IPC。
5. **上下文消耗圆环**：
   - `ChatPanel` 工具栏右上角新增 `ContextRing`（SVG 圆环）：绿 <60% / 黄 60-85% / 红 >85%，中心显示百分比；已用 = done 的 `promptTokens`，上限 = Agent `max_context`（`ctxCap` 随 agentId 拉取）。

## 阶段 8｜下载进度实时化 + 模型加载反馈 + 向量模型 idle 解释 + 数据重置安全加固 + 安装包重建 — ✅ 完成（2026-08-21）

**背景**：用户反馈 4 个问题：① 下载依赖进度条不实时更新（切界面回来才刷新）；② 本地模型服务 loading 显示半天无反馈（分不清加载中还是卡住）；③ 向量模型一直显示 idle（不知道为何不工作）；④ "删除所有数据"误删了仓库文件与 Obsidian 密钥。

**四问题修复（源码核验 + app.asar 解包 rg 双确认）**：

1. **下载进度不实时**：
   - `downloader.ts` 下载循环每 128KB 或 400ms 至少 emit 一次进度（此前仅按块写不推事件）；新增 30 秒无数据停滞检测（超时中止并报"下载连接超时"）。
   - `slime:mind:download` IPC 处理器先 `await ensureServices()` 确保进度 listener 已注册（此前 listener 未注册 → 进度事件全丢，只有切界面重拉快照才刷新 —— 用户"切界面才刷新"的直接根因）。
   - 渲染层 `App.tsx` 全局常驻订阅 `slime:mind:downloadProgress`（不再依赖 MindHubPanel 挂载）+ 下载中 1s 轮询快照兜底；`MindHubPanel` 读全局 `dl` 状态渲染进度条，实时重渲染。
   - 下载完成完整性校验：文件仍小于最小有效大小（bge 500MB / llama 1MB）→ 判失败并提示，残缺残片强制重下。
2. **loading 无反馈**：
   - `StatusPanel` 记录各角色进入 loading 的时刻，每秒重渲染显示「已等待 N 秒」（区分加载中与卡死）。
   - 本地模型加载弹窗（`App.tsx`）同样加「已等待 N 秒」计时 + 超 60 秒提示"可能卡住" + 「取消加载」按钮。
   - `model_server.ts waitReady` 检测到 llama-server 进程已退出（如模型损坏崩溃）→ 立即失败，不再空等满超时。
3. **向量模型一直 idle**：
   - 根因：嵌入模型未配置/文件缺失/llama-server 缺失时，启动失败不登记实例，状态面板看不到任何解释。
   - 修复：`ensureLocked` 启动失败也登记 idle 实例并写入具体 error（llama-server 不存在 / 模型文件不存在 / 启动失败 / 启动超时 / 模型损坏）；`status()` 在常驻 embedding 未创建实例时合成一行并给出原因。
   - `StatusPanel` 展示 idle 根因 + 「重试启动」按钮（`slime:model:startEmbedding` IPC → `mgr.startEmbedding()`）。
   - 启动时 `startup()` 后台自动预加载 embedding；bge 下载完成自动拉起（`setBgeReadyCallback`）。
4. **删除所有数据误删**：
   - 根因：旧版重置逻辑保护不足，可能波及开发机真实配置。
   - 修复：`slime:data:reset` 加三层护栏 —— ① 数据根异常（/、USERPROFILE、HOME）中止；② **开发仓库保护**（PROJECT_ROOT 含 .git 或 package.json+src → 直接拒绝并提示用安装版）；③ 仅允许删除 `config/` 下的 4 个指定文件（providers.enc.json / agents.json / sessions.json / history.jsonl），路径白名单校验。
   - 渲染层确认弹窗明确列出仅删除的 4 个文件，并声明"仓库与 Obsidian 笔记均不受影响"。
   - 全库扫描确认：其余删除操作（deleteSkill 仅 config/skills/<name>、downloader 仅下载文件）均限定在应用目录内。

## 阶段 8｜工作目录"权限不足"专项排查与修复 — ✅ 完成（2026-08-21 15:xx）

**真根因（用实测证据锁定，非猜测）**：

1. 先用真实取证确认 **工具层完全正常**：临时 vitest 直接调内置 `file_list`（能列出 `Mad Island`、`(免责声明) .txt`）与 `file_read`（能读出该 txt 正文"Like please buy genuine..."）。工具对真实绝对工作目录读写无任何问题。
2. 由此排除"工具坏了"。真正的"权限不足"来自一条隐蔽的**双校验不一致**：
   - `builtin.ts` 的 file 工具自身校验 `resolveInProject`：**先 `join(workspace, p)` 再 resolve**，相对路径正确锚定工作目录；
   - 但 `tool_loop.ts` 传给**沙箱**的 `target = args.path`（模型传的是相对路径，如 `game.exe`），沙箱 `sandbox.ts validateWorkspace(cfg.workspace, target)` 直接 `resolve(target)` **以进程 CWD 为基准**解析 → 必然不在工作目录 → 在 `checkPermission` 决策链最前面（L0 本可自动批准之前）被判 `目标 'game.exe' 超出工作目录范围` 拒绝。
3. 模型的回复"权限不足"正是 `[沙箱拒绝]` 的**直译**——即使工作目录设对、工具正常、路径也对，只要模型用相对路径调 file 工具就会触发这条误判。

**修复（3 处，全部经实测 + 单测）**：

| 文件 | 修复 |
|---|---|
| `core-ts/src/tool_loop.ts` | **相对路径锚定**：file 类工具（file_list/read/write/code_check）+ 配置了工作目录 + target 非绝对 → 先 `join(workspace, target)` 转绝对，再交沙箱校验，消除"CWD 基准误判"；同时拒因定义为 `uiIsPathTool` 仅路径类工具适用（URL 走 SSRF 不误锚定） |
| `core-ts/src/services/engine.ts` | **目录内容预注入**：`buildSystem` 装配系统提示时，若 Agent 配了工作目录，**主动调用一次 `file_list`** 把该目录当前内容清单直接写进系统提示（截断 80 项 + 计数）。模型不必调用工具就已"看得见"目录员貌（应对本地小模型不主动调工具的情况）；失败优雅降级不 crash |
| `core-ts/src/tool_loop.ts`（SandboxDecision） | **拒绝原因透传**：`SandboxDecision`/`sandboxGateFrom` 增加 `reason` 字段，沙箱拒绝时把具体原因（如"目标超出工作目录范围"）回填给模型，并附"改用工作目录相对路径/把文件放入目录重试"的指引，避免模型只看"权限不足"就放弃 |

## 阶段11：流式 Markdown 符号暴露修复（2026-08-22 13:00）

**用户反馈**：UI 以 markdown 形式流式输出长文本时，会直接暴露 markdown 格式符号（#、*、--- 等）。

**根因**：聊天面板流式输出块（ChatPanel 第 888-892 行）此前是**纯文本渲染**（`{partial || "⌛"}` + `whiteSpace: pre-wrap`），流式期间所有 markdown 符号原样显示；且 Markdown 组件对未闭合语法（如 `**重点`、单个 `#`、`-`/`--`、未闭合 ` ``` `）会当作纯文本输出，闭合后才"跳变"成样式。

**方案**（参考 Streamdown/remend 与 markdown-it 双阶段渲染的"最小补全"思路，全网检索后落地）：
1. **流式块改 Markdown 渲染**：ChatPanel 流式输出块由纯文本改为 `<Markdown text={partial} streaming />`，边输出边渲染样式。
2. **解析前最小补全**（`repairStreamingMarkdown`，仅 streaming 时生效，文本完整时各计数为偶数 = 无操作）：
   - 代码围栏：行首 ``` 数量为奇数 → 临时补结束围栏（最先处理，影响后续上下文）
   - 行内反引号：代码块外奇数 → 补一个
   - 粗体/斜体：仅统计代码块与行内代码外的未闭合 `**`/`*`（行首 `* ` 列表标记不算斜体）
3. **纯符号行跳过**（parseBlocks）：仅由 `#`/`>`/`*`/`_`/`-` 组成的行（1-6 个）跳过不渲染，避免未闭合标题/分割线/引用/列表标记暴露原始符号；`---`/`***`/`___`（3+）仍正常渲染为分割线。
4. **段落保留换行**：Markdown 段落 div 加 `whiteSpace: pre-wrap`，流式 markdown 化后多行段落不塌陷（与完成消息一致）。

**改动清单**：

| 文件 | 改动 |
|---|---|
| gui/src/renderer/pages/Markdown.tsx | 新增 repairStreamingMarkdown()（围栏/反引号/粗体/斜体最小补全，代码块与行内代码上下文感知）；parseBlocks 纯符号行跳过；段落加 whiteSpace: pre-wrap；组件新增 streaming?: boolean 属性（仅 streaming 时补全） |
| gui/src/renderer/pages/ChatPanel.tsx | 流式输出块由纯文本改为 `<Markdown text={partial} streaming />`（保留 ⌛ 占位与光标） |
