## 阶段 1｜Python sidecar 化（推理 + 嵌入 + 四阶段检索全链路）— ✅ 完成（2026-08-17）

**目标**：sidecar 独立推理服务（OpenAI 兼容端点）+ 四阶段检索 API；Node 侧将来只发查询收结果。

**交付物**：

| 文件 | 内容 |
|---|---|
| `sidecar/infer_server.py` | /health、/chat/completions（SSE 流式透传，OpenAI 兼容）、/embeddings（BGE-M3）、/stats、/models/load、/models/unload；INFER_PORT 动态端口（默认 19100）；复用 core/model_server 的 ModelServerManager/VRAMMonitor |
| `sidecar/retrieve_api.py` | /v1/retrieve 四阶段全链路：向量种子 → 链接遍历（BFS N 跳）→ 标签过滤 → 艾宾浩斯权重排序；语义复用 core/memory.py |

| `tests/test_infer_server.py` | 11 用例（fake manager/forward 注入点，run_tests + pytest 双兼容，全部 @pytest.mark.asyncio） |
| `scripts/smoke_sidecar.py` | 持久冒烟工具：full 优先（manager.ensure 链路）+ 独立 llama-server fallback 双路径；全 Python 零 PowerShell；UTF-8 控制台加固 |

**执行中发现并修复的问题**（详见 REVIEW_AGENT.md A-114）：

1. **A-115 命名冲突（架构级）**：sidecar 初名 `py/`，与 PyPI `py` 库（pytest 依赖）同名死锁——无 `__init__.py` 时 namespace 包输给 site-packages，有则 pytest 自身 `import py` 崩溃 → 改名 `sidecar/` 根治，9 处文档引用同步
2. bytes 字面量含非 ASCII → SyntaxError → 改 `.encode("utf-8")`
3. async 测试缺 `@pytest.mark.asyncio`（项目 strict 模式惯例）→ 补齐

**验证**：

- 真实冒烟 **8/9 PASS**：

## 阶段 2｜Node 壳原型（gateway + core 骨架 + 契约层）— ✅ 完成（2026-08-17）

**目标**：pnpm workspace + 契约单源（openapi.yaml → TS/Python 双端生成）+ core-ts（过滤/客户端/路由/会话）+ gateway-ts（认证/限流/转发）+ 本地硬门槛 contract:check。

**交付物**：

| 文件 | 内容 |
|---|---|
| `shared/openapi.yaml` | 契约唯一真相源（3.0.3，6 端点 + 17 schemas：chat/embeddings/retrieve/models/stats/health） |
| `scripts/gen_contracts.py` | 生成器：yaml → `shared/gen/schemas.ts`（zod + z.infer）+ `schemas.py`（pydantic v2）；`--check` 幂等防漂移；内联 object 按路径提升具名类；$ref 保留引用 |
| `core-ts/src/` | `filter.ts`（OutputFilter 全量规则移植 + A-039 遮蔽还原 + StreamFilter 跨 chunk 缓冲）、`llm/client.ts`（原生 fetch + SSE + 429 退避表 [5,15,30,60]）、`router.ts`（路由表 + 降级链声明）、`session.ts`（身份铁律 system prompt + 诚实协议 + 双路径注入骨架） |
| `gateway-ts/src/index.ts` | Fastify 网关：safeEqual 恒定时间 Bearer 认证、IP 滑动窗口限流（120/min）、CORS 收窄（origin:false）、/chat/completions /embeddings /v1/retrieve 转发（SSE 透传）、/health 豁免 |
| `scripts/contract-check.mjs` | 本地硬门槛（无 CI 替代）：① gen --check ② pytest 假数据互验 ③ vitest 假数据互验；失败即拒启动 |
| `scripts/smoke_node.mjs` | 真实闭环冒烟：起 llama-server → Session 会话流式 → 身份铁律过滤 → 收尾零残留 |
| `tests/` | vitest 67 用例（filter 14 / client 8 / router 5 / session 7 / contract 21 / gateway 12）+ `test_contract.py` 20 用例 + `fixtures_contract.json`（双端互验单源） |

**执行中发现并修复的问题**（详见 REVIEW_AGENT.md A-116）：

1. **生成器 pattern 丢失（契约双端语义分裂）**：agent_id 的 pattern 只进了 zod（.regex），pydantic 无约束 → invalid fixture 在 Python 侧通过 → 修生成器为 `Annotated[str, Field(pattern=...)]`
2. **null vs 缺失双端分歧**：fixtures 里 `error: null`——zod `optional()` 拒绝 null、pydantic 接受 → 契约语义定为"缺失或 string"，fixtures 同步
3. **pnpm 11 在 child_process 非 TTY 下吞输出且返回非 0**（两次踩坑：vitest/build）→ contract-check 与冒烟统一直调二进制（node node_modules/vitest/vitest.mjs、node node_modules/typescript/bin/tsc）
4. **TS 参数属性超出 strip-only 模式**：node 直跑 .ts 失败 → UpstreamError 改显式字段赋值（兼容 tsc/vitest/node 全运行时）
5. **llama-server 就绪判定**：/health 200 早于模型加载完成（请求 /v1/chat/completions 仍 503 "Loading model"）→ 改轮询 /v1/models
6. **限流测试隔离**：共享实例被前序用例耗尽额度 → 限流用例拆独立实例

**验证**：

- `pnpm run contract:check` 全过（生成无漂移 + pydantic 20 + zod 21）
- vitest **67/67 passed** 无告警；`pnpm typecheck`（tsc strict + noUnusedLocals）干净；`pnpm -r build` 通过
- `py qa.py` 三阶段全绿：**pytest 777 passed**（757 + test_contract.py 20）
- 真实闭环冒烟 **6/6 PASS**：llama-server 独立实例拉起 → Session 流式（10 chunks）→ 模型遵守身份铁律（输出"我是 小灵，由 slime 平台驱动"，violations=0）→ 收尾端口释放；embeddings 501 属单实例无 embedding 模型（阶段 1 已验 BGE-M3 链路）
- git：`eaff492`（契约层 + core-ts + gateway-ts + 契约双端互验 + 冒烟验收）

**里程碑**：阶段 2 达成（Node 壳原型闭环：契约双端同源 + 会话真实模型流式）。下一阶段：MCP 双栈化 / Node 侧检索端接入（L3 检索注入落真）。
